## 一句话定位

这套系统更适合被定义为一套面向 SnapGridFlow 模块化关卡生产的手工拓扑布局与构建调优工具链，而不只是一个“画格子”的编辑器。

它的核心价值不在于“能在网格上摆房间”，而在于：

- 把手工布局抽象为稳定的中间层数据，而不是直接摆放 prefab。
- 用统一方向码体系连接编辑、校验、导出、模块匹配和场景构建。
- 把自动匹配、人工替换和单节点增量重建组织成一条可迭代的生产流程。
- 让自动生成布局和手工布局最终汇入同一套 `DungeonLayoutData` 与场景构建链路。

## 项目目标与解决的问题

从当前代码看，这套工具解决的不是“策划能不能手动画一个布局”这种单点问题，而是一组典型的模块化关卡生产问题。

### 1. 手工布局容易和具体模块资源耦合的问题

如果手工布局直接以 prefab 摆放为事实源，就会遇到：

- 换主题成本高
- 模块资源调整后布局失效
- 自动布局和手工布局无法共用同一套数据结构
- 后期很难做规则校验和批量替换

这套工具通过：

- `ManualLayoutAsset`
- `ManualLayoutCell`
- `TileShape`
- `DirectionCode`
- `function`

先把布局抽象成“格子拓扑 + 语义功能”层，再在构建阶段去匹配实际模块资源。

### 2. 手工布局缺少稳定中间表达的问题

很多手工布局工具的问题在于只适合编辑，不适合进入后续构建和版本管理流程。

这套工具把手工结果导出为 `DungeonLayoutData`，并显式区分：

- `LayoutSource.Auto`
- `LayoutSource.Manual`

这意味着自动生成布局和手工绘制布局，最终都可以汇入同一套布局数据模型，而不是形成两条彼此隔离的生产链。

### 3. 模块匹配逻辑不稳定的问题

模块化关卡搭建里，真正困难的地方不在于“有多少 prefab”，而在于：

- 如何表达模块的连接方向
- 如何匹配不同主题下的语义房间
- 如何处理可旋转模块
- 如何在多个候选模块之间做稳定选择

这套工具围绕方向码、主题分类和权重随机，建立了较完整的匹配规则，使“布局拓扑 -> 模块实例”的过程更加可控。

### 4. 关卡人工微调容易污染原始布局的问题

在实际生产中，自动匹配出来的模块未必总是最合适，通常还需要：

- 替换单个节点的模块
- 保留节点级备注
- 控制主题和种子
- 后续支持节点锁定和局部偏移

这套工具没有把这些调整直接写回原始布局数据，而是专门抽出 `BuildProfile` 作为构建配置层，让“原始布局”和“构建定制”边界更加清晰。

### 5. 替换一个节点就要整图重建的问题

如果每次替换模块都要整图销毁并重建：

- 反馈慢
- 调试成本高
- Undo 体验差
- 很难做精细化迭代

这套工具在 `DungeonLayoutController` 中专门补了 `RebuildNode(nodeId)`，让单节点替换后可以局部刷新，而不影响其他已实例化模块。

### 6. 错误发现过晚的问题

手工布局最常见的问题是：

- 邻接格子连接口对不上
- 边界是否允许开口不明确
- 模块数据库里没有覆盖某种方向码

这套工具在编辑器里补了连接冲突校验和模块覆盖率检查，把很多问题提前暴露在导出前，而不是等到场景构建失败后再回头排查。

## 项目架构分层

从当前代码结构来看，这套手动布局工具大致可以拆成以下几层：

### 1. 抽象布局资产层

这一层负责回答“手工布局到底保存了什么”。

核心职责：

- 保存网格大小和模块尺寸
- 保存格子坐标、形状、旋转和功能标签
- 用方向码表达连通拓扑
- 作为可序列化、可版本管理的布局事实源

核心意义：

- 让布局编辑不再直接依赖具体 prefab。
- 为自动布局和手工布局提供统一的数据承载形式。

### 2. 方向码与拓扑建模层

这一层负责回答“格子的连通关系如何被稳定表达”。

核心职责：

- 将 4 个方向的连通组合压缩为 5 种基础 `TileShape`
- 用有限旋转生成方向码变体
- 提供方向偏移、反向方向和旋转规范化工具
- 支撑门连接生成和邻接关系校验

核心意义：

- 把复杂连接关系收敛为稳定的中间表达。
- 让编辑器、校验器和构建器围绕同一套语义工作。

### 3. 编辑交互层

这一层负责回答“用户如何绘制、查看和修改布局”。

核心职责：

- 2D 网格画布绘制
- 画笔、擦除、选择三种工具
- 形状面板和旋转选择
- 功能标签编辑
- 画布缩放和平移
- SceneView 叠加层同步预览

核心意义：

- 让抽象布局编辑具备直观且低门槛的交互体验。
- 用 2D 视图和 3D 视图联动降低理解和验证成本。

### 4. 校验与导出层

这一层负责回答“布局是否合法，以及如何进入后续构建流程”。

核心职责：

- 相邻格子连接校验
- 边界开口规则检查
- 模块覆盖率预检查
- 导出 `DungeonLayoutData`
- 生成节点门连接信息

核心意义：

- 将错误前置到编辑阶段暴露。
- 让导出结果成为后续场景构建的稳定输入。

### 5. 模块命名与匹配层

这一层负责回答“抽象布局节点如何找到合适的模块资源”。

核心职责：

- 解析模块名称中的主题和方向码
- 生成 `theme + function` 对应的 `Category`
- 将模块按旋转预展开为匹配缓存
- 支持精确匹配和退化匹配
- 支持基于权重的确定性选择

核心意义：

- 将模块匹配从散乱字符串判断升级为规则化流程。
- 让场景构建结果在可控性和随机性之间取得平衡。

### 6. 场景构建与增量重建层

这一层负责回答“布局数据如何真正落成场景，并在修改时快速反馈”。

核心职责：

- 全量构建场景
- 销毁已构建实例
- 单节点增量重建
- 根据旋转计算模块 Transform
- 维护 nodeId 到实例对象的映射

核心意义：

- 让布局数据不只是静态资产，而是真正可落场景的中间层。
- 让人工替换和调优具备更高的迭代效率。

### 7. 构建配置与人工调优层

这一层负责回答“在不污染原始布局的前提下，如何保存构建期人工决策”。

核心职责：

- 记录主题和全局种子
- 保存节点级模块替换
- 保存节点级备注
- 预留锁定、局部偏移和节点级随机种子扩展位

核心意义：

- 将原始布局数据和人工调优数据彻底分离。
- 为后续更复杂的构建控制能力留出清晰扩展点。

## 最有代表性的亮点

下面这些亮点，是后续最适合写进简历和作品集的内容。

### 亮点 1：把手工布局提升为抽象拓扑层，而不是直接摆 prefab

这套工具最重要的设计之一，是先把布局保存为：

- 网格坐标
- Tile 形状
- 旋转
- 功能标签
- 方向码

而不是直接把场景里的 prefab 摆放结果当作唯一事实源。

这个点适合在简历里表达为：

- “将手工布局抽象为拓扑与语义中间层，解耦布局编辑与具体美术模块资源”

### 亮点 2：建立了统一方向码体系，贯通编辑、校验和构建

这套工具没有在不同环节各自定义一套连接表达，而是围绕 `directionCode` 统一处理：

- 2D 网格可视化
- SceneView 箭头预览
- 连接冲突校验
- 门连接导出
- 模块匹配
- 模块旋转计算

这个点适合在简历里表达为：

- “设计统一方向码体系，贯通布局编辑、连通性校验、门连接生成与模块构建流程”

### 亮点 3：用有限基础形状压缩布局表达复杂度

从建模角度看，这套工具没有直接暴露 15 种非空方向组合，而是把它们压缩为：

- `DeadEnd`
- `Straight`
- `Corner`
- `TJunction`
- `Cross`

再通过旋转恢复全部方向码变体。

这个点适合在简历里表达为：

- “将网格连通关系压缩为少量基础 Tile 形状与旋转规则，降低编辑复杂度并提高布局表达稳定性”

### 亮点 4：模块匹配不是简单查表，而是带旋转展开的缓存匹配

在场景构建时，模块数据库中的每个模块都会根据可旋转性预展开成多个变体，并缓存为：

- `Category`
- `sortedDirCode`
- `rotationDegrees`
- `selectionWeight`

后续构建时再按节点需求快速查找。

这个点适合在简历里表达为：

- “构建模块匹配缓存，将模块按方向码和旋转预展开，提升关卡构建阶段的匹配效率与可控性”

### 亮点 5：模块选择支持精确匹配、退化匹配和确定性加权随机

当前构建流程不是单一路径，而是做了清晰的优先级：

- `BuildProfile` 手动替换优先
- `theme + function + directionCode` 精确匹配
- 仅按 `directionCode` 退化匹配
- 基于节点专属种子的加权随机选择

这套策略兼顾了稳定性、容错性和内容多样性。

这个点适合在简历里表达为：

- “设计模块匹配优先级链，支持精确匹配、退化匹配和确定性加权随机，提高构建容错性与结果稳定性”

### 亮点 6：同一全局 seed 下，节点级随机结果仍然可重现

构建时不是简单用全局随机数，而是把：

- 全局 seed
- nodeId hash

组合成节点专属随机种子，这样既能控制整体一致性，也能保证单节点选择结果可重现。

这个点适合在简历里表达为：

- “将全局 seed 与 nodeId 组合为节点级确定性随机种子，保证模块选择结果可重现且具备节点粒度差异”

### 亮点 7：把人工替换从原始布局中剥离成独立构建配置层

`BuildProfile` 这一层很关键，它说明这套工具不是把各种手工修改直接写回布局资产，而是明确区分：

- 原始布局数据
- 构建期人工替换和备注

这个点适合在简历里表达为：

- “设计 BuildProfile 构建配置层，将原始布局数据与节点级人工替换、主题和种子配置解耦”

### 亮点 8：支持单节点增量重建，而不是每次整图全量刷新

这一点非常像真实生产工具的设计：

- 替换单个节点模块
- 清除替换恢复自动匹配
- 仅重建对应 nodeId 实例

都可以通过 `RebuildNode(nodeId)` 完成，而不是整图销毁重建。

这个点适合在简历里表达为：

- “实现节点级增量重建能力，替换单个模块后仅刷新对应节点，显著提升关卡迭代效率”

### 亮点 9：在导出前做连通性和模块覆盖率双重校验

这套工具在手工布局阶段就会检查：

- 相邻格子的连接口是否对得上
- 网格边界是否允许开口
- 当前模块数据库是否覆盖所有需要的方向码

这个点适合在简历里表达为：

- “建立导出前校验机制，提前发现拓扑冲突与模块覆盖缺失，降低构建阶段返工成本”

### 亮点 10：提供 2D 网格编辑和 3D SceneView 叠加的双视图体验

你不是只做了一个平面窗口，而是让：

- 2D 网格负责高效编辑抽象布局
- 3D SceneView 负责空间理解、冲突提示和选中同步

这说明你对工具体验也有完整考虑。

这个点适合在简历里表达为：

- “设计 2D 网格编辑与 3D SceneView 叠加联动的双视图工作流，提升抽象布局编辑的可理解性与验证效率”

### 亮点 11：自动布局和手工布局最终收敛到同一布局数据模型

`DungeonLayoutData` 同时支持：

- `Auto`
- `Manual`

这意味着手工布局不是额外的孤立支线，而是正式接入了已有布局构建链路。

这个点适合在简历里表达为：

- “打通自动生成布局与手工布局的数据模型，使两种生产方式共用同一套布局资产与场景构建流程”

### 项目介绍

这套工具面向 SnapGridFlow 模块化关卡生产，目标不是只做一个“画格子”的编辑器，而是把手工布局编辑、拓扑校验、布局导出、模块匹配、人工替换和场景重建组织成一条完整的工具链。项目通过抽象布局中间层解耦布局拓扑与具体美术模块，使自动生成布局和手工绘制布局能够共用同一套布局数据和构建流程，显著提升了关卡生产的灵活性与可维护性。

### 主要工作

#### 整体设计

1. 抽象布局中间层设计：我没有把手工布局直接做成 prefab 摆放结果，而是抽象为 `TileShape`、旋转、方向码和功能标签组成的中间层数据，让布局编辑和实际模块资源解耦，也为自动布局与手工布局统一收口提供了基础。

2. 统一方向码与连通规则：我围绕方向码建立了统一的拓扑表达方式，让网格编辑、连接校验、门连接生成、模块匹配和最终场景构建都围绕同一套规则运行，降低了编辑态和构建态不一致的问题。

3. 构建配置分层设计：我将原始布局数据和人工构建调优拆成两层，前者只保存抽象布局事实，后者通过 `BuildProfile` 保存主题、种子、节点级替换和备注，避免人工微调污染原始布局资产。

4. 自动匹配与人工替换协同：我把模块自动匹配、人工替换和场景重建串成一条统一流程，使关卡生产既可以保持批量自动化能力，也支持设计师按节点做精细化干预。

#### 重点模块

1. 手工布局编辑器：我实现了 2D 网格编辑窗口与 3D SceneView 叠加层联动，支持绘制、擦除、选择、旋转、功能标注、冲突提示和场景同步选中，提升了抽象布局编辑的可视化体验。

2. 方向码与拓扑建模：我将格子的四方向连通关系压缩为少量基础 Tile 形状和旋转规则，再统一映射为方向码，作为布局校验、门连接生成和模块匹配的核心中间表达。

3. 模块匹配缓存：我围绕模块数据库构建了 `Category + DirectionCode` 维度的匹配缓存，并对可旋转模块做预展开，支持精确匹配、退化匹配和基于节点种子的确定性加权随机选择。

4. BuildProfile 构建配置层：我设计了独立的构建配置资产来承接节点级模块替换、主题、种子和备注，使原始布局数据与人工调优数据职责分离，便于后续持续演进。

5. 节点级增量重建：我在场景构建控制器中实现了单节点增量刷新能力，替换或清除某个节点的模块后只重建对应实例，而不需要整图全量销毁重建。

6. 导出前校验与收口：我补充了连接冲突校验和模块覆盖率检查，并将手工布局导出为统一的 `DungeonLayoutData` 资产，让手工布局正式进入既有布局构建和场景展示主链路。
