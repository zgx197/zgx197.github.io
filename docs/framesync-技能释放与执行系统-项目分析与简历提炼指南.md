## 一句话定位

这套系统更适合被定义为一套面向确定性 ECS 帧同步战斗的技能释放、调度与执行框架，而不只是一个“按技能表播效果”的运行时模块。

它的核心价值不在于“技能能放出来”，而在于：

- 把玩家输入、AI 行为、Buff 触发、机关触发等多种入口统一收敛到同一条技能释放链路。
- 把技能配置、施法校验、技能实例创建、按帧能力执行、命中检测、伤害结算和表现播放组织成一条稳定闭环。
- 把逻辑层能力和表现层能力拆开调度，在保证确定性的前提下兼顾战斗逻辑和客户端表现联动。

## 项目目标与解决的问题

从当前代码看，这套系统解决的不是“一个技能如何扣血”这种单点问题，而是一组典型的运行时技能系统问题。

### 1. 技能释放入口分散的问题

真实项目里，技能不只会从玩家点击按钮触发，还会来自：

- 玩家输入
- AI 行为树
- 被动或触发技能
- Buff 连锁触发
- 技能内部继续释放的子技能
- 特定状态下的通用技能
- 机关或特殊交互技能

这套系统通过统一的 `StartSkill` 信号和 `FightSkillCastComponent` 侧的治理逻辑，把这些入口逐步收敛到同一条施法主链路中。

除了统一入口之外，施法侧还沉淀了与战斗上下文相关的释放条件判断，例如关联技能冷却就绪、是否处于被包围状态、同伴是否已在场等，使“技能什么时候允许释放”不再完全散落在 AI 分支里。

### 2. 技能运行时状态难以管理的问题

技能一旦进入运行时，往往就要处理：

- 当前是否正在施法
- 是否占用角色动作
- 是否需要脱手执行
- 是否需要独立技能实体
- 技能是否被打断或取消
- 技能内部多个能力的触发顺序和依赖关系

这套系统通过 `FightSkillCastComponent`、`FightSkillExecuteComponent` 和 `AbilityInstance` 状态机，把“技能释放”和“技能执行”明确拆成两层来管理。

同时，技能链中继续释放子技能时，并没有另外再走一套“特殊分支脚本”，而是通过释放技能能力把新的技能请求重新送回统一入口；机关交互也不是写死在某个技能里，而是通过机关交互执行组件、机关技能执行系统和机关子系统路由，接入同样的运行时能力模型。

### 3. 逻辑层和表现层难以兼顾的问题

技能系统最常见的矛盾之一，是：

- 逻辑层要求严格确定性
- 表现层要求灵活联动动画、特效、音效

这套系统通过“逻辑层能力”和“表现层能力”双轨并行调度，让伤害、位移、Buff、信号触发等逻辑能力走确定性执行链路，而动画与表现轨则按帧查询驱动并同步给 View 层。

### 4. 技能能力扩展成本高的问题

如果每加一种技能能力，都要在技能系统主循环里硬编码一堆分支，系统很快会失控。

这套系统把不同能力拆成独立执行器，例如：

- 单次攻击
- 连续攻击
- 冲锋
- 瞬移
- 子弹发射
- 加 Buff
- 触发信号
- 机关相关能力

这样技能系统主干负责调度，具体能力逻辑由执行器分担，降低了扩展和维护成本。

### 5. 命中检测、子弹和伤害结算难以统一的问题

真实战斗里，技能伤害来源可能并不相同：

- 近战范围打击
- 持续范围伤害
- 子弹飞行命中
- Buff 造成的持续伤害

这套系统围绕统一的伤害流程构建了从命中目标收集、伤害数据组装、前后置信号、血量与躯干值处理、死亡判定到客户端事件派发的完整链路，使不同技能形态能进入同一套结算体系。

### 6. 技能配置与运行时脱节的问题

如果运行时只认旧表结构或散乱配置，技能系统会越来越难演进。

这套系统已经明显转向以 `SkillConfigAsset` 为核心的技能运行时配置模型，支持：

- 技能元信息
- 逻辑层能力分组
- 表现层能力分组
- 技能索敌和释放条件
- 技能类型和动作类型

这让技能运行时不再只是“读表 + if else”，而是逐渐进入配置驱动的结构化执行模式。

## 项目架构分层

从当前代码结构来看，这套技能释放与执行系统大致可以拆成以下几层：

### 1. 技能配置资产层

这一层负责回答“技能在运行时如何被结构化描述和快速查询”。

核心职责：

- 保存技能基础元信息
- 保存技能类型、动作类型和释放条件
- 保存逻辑层能力分组
- 保存表现层能力分组
- 构建按帧和按 ID 的查询索引

核心意义：

- 让技能运行时有明确的配置事实源。
- 让技能执行系统可以按帧、按能力 ID、按技能类型稳定读取数据。

### 2. 施法治理层

这一层负责回答“一个实体什么时候可以放技能，以及放的是哪个技能”。

核心职责：

- 当前技能记录
- 单技能冷却
- 同组技能冷却
- 公共冷却
- 已学技能集合管理
- 释放条件检查与战斗上下文判断
- 触发技能与主动技能入口统一
- 技能优先级和特殊技能处理

核心意义：

- 把“技能是否能释放”从散落判断收敛到统一组件和规则中。
- 支撑玩家、AI、Buff 和状态技共用同一套施法治理能力。

### 3. 技能释放与实例创建层

这一层负责回答“收到技能释放请求后，如何把它变成真正运行中的技能实例”。

核心职责：

- 统一接收 `StartSkill` 信号
- 技能配置查询
- 技能冷却校验
- 动作技能 / 脱手技能分流
- 必要时创建独立技能实体
- 初始化技能执行组件

核心意义：

- 将技能释放从“发个事件”升级为结构化的实例创建过程。
- 为动作技能和脱手技能提供统一但可区分的运行模型。

### 4. 技能执行状态机层

这一层负责回答“一个技能在运行过程中如何按帧推进，并管理内部多个能力的状态”。

核心职责：

- 技能执行状态管理
- 技能启动时的能力实例预展开
- 能力实例列表维护
- AbilityId 到实例索引映射
- Pending / Running / Complete / Interrupted / Cancelled 状态流转
- 阻塞能力和依赖能力管理
- 技能中断与取消

核心意义：

- 让技能执行不再只是“当前帧跑一遍列表”，而是有明确状态机。
- 让复杂技能的多能力串联、依赖和打断行为可控。

### 5. 逻辑层能力执行层

这一层负责回答“哪些能力会影响确定性战斗逻辑，以及如何执行”。

核心职责：

- 单次攻击能力
- 连续攻击能力
- 冲锋能力
- 瞬移能力
- 子弹发射能力
- 加 Buff 能力
- 信号触发能力
- 机关相关能力

核心意义：

- 把技能效果拆成可扩展的能力执行器模型。
- 让新能力接入不必不断膨胀技能系统主循环。

### 6. 表现层能力联动层

这一层负责回答“技能的动画和表现如何在不破坏确定性的前提下联动起来”。

核心职责：

- 按帧获取表现层能力
- 动作 Timeline 播放
- 动画状态机联动
- 直接播放技能表现
- 命中反馈与 Buff 表现

核心意义：

- 让技能逻辑和表现解耦，但仍保持同帧联动。
- 为客户端动画、特效、音效留出更稳定的接线点。

### 7. 命中检测与伤害结算层

这一层负责回答“技能命中谁、如何结算伤害、如何触发生命与控制变化”。

核心职责：

- 范围命中检测
- 子弹命中检测
- 技能伤害数据组装
- 前后置信号
- 扣血、躯干值变化和死亡检测
- 受击表现事件派发

核心意义：

- 把不同技能形态的伤害流程收拢到统一结算体系。
- 让战斗逻辑、属性、Buff 和表现反馈围绕同一份伤害上下文运转。

### 8. 子弹与持续运动子系统层

这一层负责回答“飞行物、持续位移和持续性技能如何脱离瞬时技能执行后继续运行”。

核心职责：

- 子弹发射器实体创建
- 弹道控制
- 命中穿透统计
- 子弹销毁
- 冲锋位移更新
- 冲锋终止条件判定
- 持续攻击的触发节奏控制
- 牵引类效果与导航约束处理

核心意义：

- 把需要跨多帧运行的技能效果从瞬时执行中解耦出来。
- 让子弹、冲锋这类持续性能力拥有独立生命周期。

### 9. 触发源接入层

这一层负责回答“玩家、AI、Buff 和其他系统如何接入技能释放主链路”。

核心职责：

- 玩家技能点击接入
- AI 行为树释放技能
- Buff 连锁触发技能
- 状态技 / 通用技触发
- 子技能继续施放
- 机关交互与机关技能触发

核心意义：

- 让技能系统成为战斗里的公共能力，而不是只服务某一种入口。
- 让子技能和机关联动也能复用同一套主链路，而不是分裂成额外分支。
- 提升技能系统在整套战斗仿真中的复用度。

## 最有代表性的亮点

下面这些亮点，是后续最适合写进简历和作品集的内容。

### 亮点 1：统一了多来源的技能释放入口

这套系统不是只响应玩家点击，而是把以下来源逐步统一到同一条技能释放链路上：

- 玩家输入
- AI 行为树
- Buff 触发
- 特殊状态技能
- 子技能继续施放
- 机关交互触发的后续技能

这个点适合在简历里表达为：

- “统一玩家、AI、Buff 与触发技能的释放入口，建立面向战斗仿真的通用施法主链路”

### 亮点 2：把技能释放和技能执行拆成两层治理

当前代码里，技能并不是“检测到按钮就直接执行伤害”，而是明确分成：

- 施法治理层
- 技能实例执行层

前者管冷却、组别、公 CD、当前技能和是否能释放，后者管技能执行状态、能力调度和生命周期。

更重要的是，施法层并不只做冷却校验，还额外承接了与战斗上下文相关的释放条件判断，例如关联技能冷却是否就绪、角色是否被包围、同伴是否已经参战等。

这个点适合在简历里表达为：

- “拆分技能施法治理与技能实例执行两层结构，统一处理冷却校验、释放条件判断、技能调度与运行时状态推进”

### 亮点 3：技能执行采用能力实例状态机，而不是单纯按帧遍历

这套系统已经不是简单的“到第几帧执行哪条配置”，而是给逻辑层能力建立了 `AbilityInstance` 状态机：

- Pending
- Running
- Complete
- Interrupted
- Cancelled

并支持：

- 阻塞能力
- 依赖触发
- 能力级中断
- 技能级取消

从实现方式上看，技能开始执行时会先把逻辑层能力预展开为运行时实例列表，并建立能力 ID 到实例索引的映射，后续再根据触发帧或依赖完成关系去推进状态，而不是每帧反复扫描原始配置做临时判断。

这个点适合在简历里表达为：

- “设计技能能力实例状态机，在技能启动阶段完成能力实例化与依赖映射，支持阻塞、依赖触发、技能中断与能力级打断”

### 亮点 4：逻辑层和表现层做成双轨调度

这是一条很有辨识度的设计：

- 逻辑层能力走确定性执行链路
- 表现层能力按帧触发并联动动画系统

这样既保证了伤害、位移、Buff 等逻辑能力可预测，也让动画和特效播放具备足够灵活性。

这个点适合在简历里表达为：

- “将技能运行时拆分为逻辑层与表现层双轨调度，在保证确定性的前提下统一逻辑执行与动画表现联动”

### 亮点 5：能力系统做成了执行器框架，而不是分散硬编码

当前技能能力已经被拆成多个独立执行器，例如：

- 单次攻击
- 连续攻击
- 冲锋
- 瞬移
- 子弹发射
- 加 Buff
- 触发信号

这说明你搭建的不是某一个技能的脚本，而是一套可扩展的技能能力执行框架。

这个点适合在简历里表达为：

- “搭建技能能力执行器框架，将攻击、位移、子弹、Buff、信号等效果解耦为可扩展能力模块”

### 亮点 6：动作技能与脱手技能拥有不同的运行模型

代码里已经明确区分：

- 动作技能直接挂在施法者身上执行
- 脱手技能会创建独立技能实体承载执行逻辑

这使技能系统能同时支撑角色占用动作的技能和脱手持续运行的技能。

这个点适合在简历里表达为：

- “区分动作技能与脱手技能的运行模型，为角色本体执行与独立技能实体执行提供统一支持”

### 亮点 7：子弹链路是完整的，不只是发一个投射物

这套系统里的子弹链路已经包括：

- 子弹发射器创建
- 扇形 / 矩形 / 单发等发射模式
- 弹道控制
- 形状投射命中检测
- 穿透统计
- 命中特效和销毁流程

这个点很适合体现你在运行时战斗系统上的工程深度。

这个点适合在简历里表达为：

- “构建完整子弹链路，覆盖发射器生成、弹道更新、命中检测、穿透统计与命中反馈流程”

### 亮点 8：冲锋、持续攻击等持续性能力拥有独立生命周期与节奏治理

这套系统对持续性能力的处理不是“挂个持续时间然后每帧扣血”这么简单，而是分别拆出独立系统持续更新，并处理：

- 时间到期
- 障碍碰撞
- 不可行走区域
- 到达目标
- 外部中断
- 持续攻击的动态触发频率
- 命中驱动的加速与衰减
- 牵引目标时的导航约束

这个点说明你对“持续性技能效果”的运行时治理有明确设计。

这个点适合在简历里表达为：

- “为冲锋、持续攻击等持续性技能效果建立独立生命周期系统，统一处理位移推进、节奏控制、终止条件与中断逻辑”

### 亮点 9：伤害结算链路做成统一上下文流程

这套系统里的伤害并不是在命中处直接写死扣血，而是先组装 `DamageInfo`，再经过：

- 技能或 Buff 来源识别
- 属性和倍率组装
- 前后置信号
- HP / 躯干值变化
- 死亡检测
- 客户端事件派发

这个点很适合体现你对战斗数值和运行时事件链的组织能力。

这个点适合在简历里表达为：

- “建立统一伤害上下文与结算流程，串联技能命中、属性计算、控制状态、死亡判定与客户端反馈”

### 亮点 10：技能配置已经进入结构化、可索引的资产模型

运行时配置不只是一个大表，而是逐步沉淀成以 `SkillConfigAsset` 为核心的结构化模型，支持：

- 技能元信息
- 能力按帧分组
- 能力按 ID 索引
- 逻辑层 / 表现层分离
- 技能类型和释放条件

这个点适合在简历里表达为：

- “推动技能运行时从散乱配表向结构化技能资产演进，支持按帧、按能力和按类型的高效查询”

### 亮点 11：表现系统和确定性逻辑之间建立了明确桥梁

这套系统没有把表现完全塞进逻辑层，而是通过：

- 当前动作 Timeline 标识
- `PlayAnimOrSkillComponent`
- Timeline 数据表
- 命中与 Buff 表现事件

把确定性逻辑和客户端表现连接起来。

这个点适合在简历里表达为：

- “打通确定性技能逻辑与 Timeline 表现系统，通过动作 Timeline、表现能力与客户端事件建立运行时桥梁”

### 亮点 12：支持子技能链式释放与运行时信号扩展

从 `SkillTriggerSignalAbilityActuator` 和 `SkillCastSkillAbilityActuator` 可以看出，这套系统已经支持：

- 技能内部触发信号
- 运行时继续释放其他技能
- 技能与机关、掉落、侍从生成等系统联动

更关键的是，子技能不是通过独立脚本临时拼出来的，而是通过“释放技能能力”在运行时再次发起 `StartSkill`，把新的技能重新送回统一施法入口。这样主技能、触发技能和子技能共享同一套冷却、实例化、执行与收尾逻辑。

这说明技能系统已经不是孤立模块，而是战斗仿真里的触发中枢之一。

这个点适合在简历里表达为：

- “支持技能内部信号与子技能链式释放，通过统一入口承接主技能与后续技能链路，增强系统联动能力”

### 亮点 13：机关联动复用了同一套运行时能力模型

机关联动这部分并不是完全独立于技能系统之外的另一套黑盒逻辑，而是做了比较清晰的接入分层：

- 人物或技能先触发机关交互信号
- 机关交互系统根据机关类型和子类型路由到对应机关子系统
- 子系统决定是播放人物交互技能、播放机关技能，还是直接触发机关事件
- 机关技能继续通过机关技能执行组件与机关技能执行系统按帧推进
- 机关能力依然复用统一的能力执行器框架

这意味着机关联动虽然有自己的交互上下文和子系统分发层，但底层仍然和技能运行时共享“技能配置 + 按帧执行 + 能力执行器 + 生命周期结束回调”这套模型。

这个点适合在简历里表达为：

- “设计机关交互到机关技能的统一接入链路，通过交互系统、子系统路由与机关技能执行组件，将机关联动接入同一套运行时能力模型”

### 项目介绍

这套系统是游戏运行时中的技能释放与执行主链路，目标不是只让技能“能释放、能扣血”，而是统一承接技能施法、技能实例调度、按帧能力执行、命中检测、伤害结算和表现联动流程。项目围绕技能配置资产、施法组件、执行组件、能力执行器、子弹系统和伤害结算系统逐步建立出一条完整闭环，使技能运行时从分散逻辑逐步演进为结构化、可扩展、可联动的确定性战斗框架。

### 主要工作

#### 整体设计

1. 技能施法与技能执行双层结构设计：我没有把技能系统做成“检测输入后立刻执行效果”的单层逻辑，而是拆分出施法治理层和技能执行层。前者负责技能冷却、同组技能、公 CD、释放条件和触发技能判断，后者负责技能实例创建、运行状态推进和能力调度，使技能系统在复杂战斗场景中仍然保持清晰边界。

2. 统一多来源技能触发入口：围绕运行时战斗需求，我把玩家输入、AI 行为树、Buff 连锁触发、状态技、子技能继续施放以及机关交互触发的后续技能等多种入口逐步收拢到同一条技能释放主链路中，避免技能释放逻辑散落在各个系统里难以治理。

3. 逻辑层与表现层双轨调度：为了兼顾帧同步逻辑和客户端表现，我将技能配置拆成逻辑层能力和表现层能力两条轨道。逻辑层负责伤害、位移、Buff 和信号等确定性效果，表现层则负责动作 Timeline、动画和表现联动，使运行时既稳定又具备足够的表现灵活性。

4. 技能配置资产结构化：我围绕运行时技能数据逐步建立了结构化的技能配置资产模型，使技能不再只是依赖散乱表结构，而是能以“基础元信息 + 逻辑能力分组 + 表现能力分组 + 查询索引”的方式被组织和读取，为后续编辑器接入和系统演进提供基础。

#### 重点模块

1. 施法治理与冷却系统：我在施法组件中统一管理技能冷却、技能组共用冷却、公 CD、当前技能和已学技能等状态，同时支持触发技能和主动技能共用同一套释放治理逻辑，并补充了关联技能冷却、被包围判定、同伴在场等释放条件检查，让角色、怪物和被动触发都能走统一施法校验流程。

2. 技能实例与能力状态机：我为技能执行组件设计了独立的技能状态与能力实例状态管理机制，支持 Pending、Running、Complete、Interrupted、Cancelled 等状态流转，并在技能启动阶段先将逻辑层能力预展开为运行时实例，建立能力 ID 与实例索引映射，再叠加阻塞、依赖和打断逻辑，使复杂技能不再只能靠时间顺序硬跑配置。

3. 能力执行器框架：我把攻击、冲锋、瞬移、子弹发射、加 Buff、触发信号和机关类能力拆成独立执行器，通过统一接口接入技能执行系统。这样新增能力时不需要反复膨胀主循环，而是可以在保持主链路稳定的前提下扩展新的能力类型。

4. 子技能链与机关联动接入：我把子技能继续释放设计成运行时再次发起技能请求，而不是写成独立的脚本分支；同时把机关交互拆成机关交互系统、机关子系统路由、机关技能执行组件和机关技能执行系统，使机关技能也能复用技能配置、按帧执行、能力执行器和结束回调这套运行时模型。

5. 子弹与持续性能力子系统：我实现了子弹发射器、弹道推进、命中检测、穿透统计和销毁流程，同时为冲锋、持续攻击等持续性能力补了独立系统，处理时间到期、碰撞、不可行走区域、到达目标、动态触发频率、命中驱动加速和牵引效果等运行时问题，让持续性技能效果拥有明确生命周期与节奏控制能力。

6. 统一伤害结算链路：我围绕 `DamageInfo` 组装了技能伤害、Buff 伤害和回血等统一数据流程，并把前后置信号、属性计算、血量与躯干值变化、死亡判定以及客户端反馈事件串成一条链路，使不同技能形态都能进入同一套结算体系。

7. 技能与表现系统联动：我将技能执行和 Timeline 表现系统打通，使技能在确定性逻辑推进的同时，可以同步驱动动作 Timeline、命中反馈、Buff 表现和客户端动画事件，避免战斗逻辑和表现系统各自为政。
