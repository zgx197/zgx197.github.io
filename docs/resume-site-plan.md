# 简历站点路线图

## 目标

我们希望把当前个人网站逐步演进成一套稳定的“简历驱动建站框架”，核心链路如下：

`简历原文 / PDF -> 通用结构化数据 -> 人工修订 -> 网站页面自动生成`

这套框架的重点不是只服务当前这一个站点，而是把内容、样式、页面逻辑拆开，让后续新增项目、替换简历、补图片视频时都尽量少改代码。

## 当前进度

目前已经具备的基础能力：

- 已有简历数据结构层与页面读取层。
- 已支持从 `txt` / `pdf` 导入简历草稿。
- 已有 `merge-imported-resume` 第一版，可以把导入结果和正式数据做安全合并。
- 当前网站页面已经基本建立在统一数据源之上。

当前还欠缺的主要是：

- 更稳定的数据校验能力。
- 更清晰的人工修订层。
- 更完整的媒体素材约定。
- 更顺手的导入、检查、合并工作流。

## 阶段规划

### P0：先做出可用框架

这个阶段的目标是把“导入一份简历并生成整站”真正跑通，形成最小闭环。

这一阶段需要完成的事情：

- 明确并冻结 `resume schema v1`，让字段语义清晰、结构稳定。
- 增加 schema 校验，提前发现 `slug` 冲突、引用丢失、日期格式异常、链接非法等问题。
- 升级导入报告，让我们能快速判断哪些内容可以直接用，哪些需要人工补。
- 增加独立的人工修订层，不让后续重新导入覆盖掉已经打磨过的正式内容。
- 继续强化 merge 逻辑，让合并默认安全、结果可预期。
- 确保首页、about、resume、项目详情页全部只读统一数据源。
- 约定项目素材目录和最基础的图片 / 视频读取规则。

阶段完成标准：

- 一份 PDF 简历可以稳定导入成结构化数据。
- 导入结果可以被校验、被人工修订、被安全合并。
- 网站主要页面都能从统一结构自动生成。

### P1：提升稳定性和可维护性

这个阶段的目标是让框架更适合长期迭代，而不是只够当前先跑起来。

这一阶段需要完成的事情：

- 继续提升解析质量，重点优化 `profile`、`skills`、`education`、`honors`、项目归属和指标提取。
- 为导入结果增加更清晰的元信息，比如导入来源、时间、低置信度提示。
- 增加导入前后的 diff 预览，方便在真正写入正式数据前先检查变化。
- 把解析规则进一步模块化，降低后续继续补规则时的维护成本。
- 完善页面缺省策略，保证没有图片、没有视频、没有指标时页面依然自然。
- 补齐 SEO 和页面元信息生成逻辑。

阶段完成标准：

- 导入质量明显更稳，人工清洗成本下降。
- 数据修改更可追踪，合并更透明。
- 页面在内容不完整时也能保持较好的展示质量。

### P2：把它做成可复用产品

这个阶段的目标是从“当前个人网站框架”进一步走向“可复用的简历网站生成器”。

这一阶段需要完成的事情：

- 支持多份简历输入，生成不同版本的网站内容。
- 支持中英文等多语言内容结构。
- 支持更丰富的项目素材组织方式，例如长文案例、架构图、录屏、附件等。
- 增加轻量编辑工具，减少直接改 TS / JSON 的成本。
- 支持导出通用 JSON，方便未来接 CMS 或切换前端实现。
- 在保证人工修订优先的前提下，引入 AI 辅助提炼能力。

阶段完成标准：

- 这套方案不再只适用于当前仓库，而是可以迁移到别的个人站或作品集项目。

## 推荐顺序

如果我们按性价比最高的方式继续推进，建议顺序如下：

1. 先做 `schema 校验`
2. 再做 `人工修订层`
3. 再做 `导入报告增强`
4. 然后继续补 `merge` 能力
5. 最后推进 `素材约定 + 项目详情页素材驱动`

## 第一版完成标准

当下面这些都成立时，可以认为第一版框架已经搭好了：

- 简历可以从原文或 PDF 自动导入。
- 导入结果可以自动检查问题。
- 正式内容和导入内容已经分层。
- 重新导入不会轻易覆盖人工打磨内容。
- 所有主要页面都从统一数据结构生成。
- 项目页可以按约定读取图片、视频和外链素材。

## 下一步建议

下一步最值得直接开工的是这三项：

- `schema 校验`
- `人工修订层`
- `导入报告增强`

这三项做完之后，当前这套简历驱动网站的骨架就会稳很多，后面无论是继续补项目内容，还是继续美化页面，都会更顺手。
